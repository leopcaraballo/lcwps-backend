## 1. AI Code Generation Policy

### 1.1 Permitted Use Cases

Allowed:

- Boilerplate code (controllers, repositories)
- Unit test generation (with human verification)
- Documentation generation
- SQL query suggestions (reviewed before execution)
- Configuration files (YAML, JSON)
- Architecture diagrams (Mermaid)

Prohibited:

- Security-critical code (encryption, auth, RLS policies)
- Core business logic (domain entities, aggregates)
- Financial calculations without formal verification
- Direct production deployments without human review

---

---

## 3. Security Requirements for AI Code

- Security-related AI output requires **3+ human reviewers**.
- SAST must pass with zero critical/blocker issues.
- AI-generated code must include tests for happy path and error paths.

---

## 4. AI Governance Board

**Meets:** Monthly (1st Thursday)
**Attendees:** CTO, Chief Architect, CISO, Lead Developer

---

## 5. Prohibited AI Practices

- Direct AI deployment without human review
- AI-generated database migrations without DBA review
- AI-generated regulatory documents without legal review
- Automation that bypasses two-person control
